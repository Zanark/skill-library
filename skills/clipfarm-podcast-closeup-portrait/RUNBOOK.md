## Build the mouth treatment for the actual art

1. Freeze the selected image/reference hash; fit each host face perspective.
2. Remove/repair only the original printed mouth area using local skin geometry.
   Do not copy laptop, glasses or adjacent facial pixels into moving sprites.
3. Define a useful variety of supplied mouth shapes, transformed independently
   to each face's angle/size. More random changes are not better lip-sync.
4. Build source-specific estimated mouth events constrained by speaker spans and
   actual silence. Keep inactive/silent mouths appropriately still.
5. Evaluate events on the 30fps output clock, without changing audio or adding
   cumulative phase delay.
6. Inspect actual encoded shape variety and transitions against speech; disclose
   approximate alignment rather than claiming forced-aligned phonemes.

V2's median active hold was about 66.7ms in the accepted reference direction;
V3-V6's roughly 267-300ms holds were too slow for this user. V7 changed 640 to
632 shape transitions while retaining all 40 available shapes. Those are facts
about that exact source, not a universal mouth-event count or a rule to eliminate
every one-frame event in unrelated speech.

At 30fps a qualitative "barely slower" request cannot be measured in literal
microseconds. Preserve turn/silence boundaries; do not slow playback, stretch
speech or leave the wrong host talking to meet a mouth-hold target.
