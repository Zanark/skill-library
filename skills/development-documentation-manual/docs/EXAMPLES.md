# Case studies and transfer limits

These are reviewed documentation techniques, not new execution results or
claims that every project has been exhaustively audited. Source IDs resolve in
[SOURCES.md](SOURCES.md). Public-safe descriptions do not reproduce source bodies.

## 1. TrickRoom: the complete development loop

**Sources:** TR-01, TR-02, TR-03.

The workflow guide connects a numbered TODO system, focused implementation,
tests, documentation and journals. A real journal example distinguishes direct
method checks from exercising the actual GUI signal path. The book instructions
add AST-resolved symbol citations and real PDF layout review.

**Transfer:** define work by observable outcome; test the boundary that failed;
update the causal journal and user/maintainer guide together.

**Limit:** its Python citation resolver and book page budget are project-specific.
Do not prescribe its dependencies for every language or impose PDF production
on a small unrelated change.

## 2. ClipFarm: planning is not a production receipt

**Sources:** CF-01, CF-02, CF-03.

Product decisions, delivery workstreams and development ledger serve separate
roles. Reusable workflow definitions coexist with individual run evidence.
Reviewed editing depends on full transcript understanding, source-time maps,
immutable drafts, output ASR and actual encoded motion/join review.

**Transfer:** maintain canonical procedures plus separate run receipts. Preserve
source/output identity and a coverage/action ledger.

**Limit:** a completed custom producer does not prove a reusable feature exists.
The dedicated editorial skill remains authoritative for actual media work.

## 3. Phantom Fudge: atlas-before-handbook maintenance

**Sources:** PF-01, PF-02, PF-03.

Workflow and documentation-maintenance guides define coupled updates. The atlas
accounts for first-party physical lines using reviewed hashes/ranges and authored
explanations. The handbook then teaches the system at a higher level.

**Transfer:** give completeness claims an explicit scope and mechanical checks,
then separately review semantic quality.

**Limit:** do not update a hash to conceal stale explanations. An atlas is an
expensive mode selected deliberately, not a mandatory default for all projects.

## 4. EntropyTag: explanation and promotion before scale

**Sources:** ET-01, ET-02, ET-03.

Contributor instructions favor a small-first implementation/promotion boundary.
The documentation foundation includes design, architecture, assets, quality,
risks, glossary, catalogue and granular TODOs. The ledger records actions,
immediate effects, reasons, mechanisms and evidence.

**Transfer:** document planned versus implemented behavior explicitly; keep the
development story causal rather than a list of commit titles.

**Limit:** the planning package's existence is not proof that the planned game
systems are implemented. Human promotion gates remain local requirements.

## 5. SpriteCanvas: source-linked engineering handbook

**Sources:** SC-01, SC-02.

The handbook organizes subsystem explanations, algorithms/design principles,
testing and navigation with source citations and meaningful diagrams.

**Transfer:** provide both first-principles reading and maintainer lookup.
Explain mechanisms and invariants rather than repeating class names.

**Limit:** do not assume every project wants SpriteCanvas's front-page density.

## 6. KardboardCode: several documentation truth models

**Sources:** KC-01 through KC-05.

The engineering handbook is living. The packaged book is an edition. The video
script package supports production. DevelopmentJourney freezes a sanitized
historical corpus. The complete GUI reference accounts for declared surfaces,
themes, controls and scrolling parts with embedded screenshots.

**Transfer:** give each family its own canonical source, audience, freshness,
manifest and completion gates. A frozen documentary must not drift with current
feature state. A visual reference needs a coverage matrix.

**Limit:** exact image/surface/page counts, the front-page image contract and
earlier per-TODO commit authorization are not universal policies.

## 7. B-Bakery: image-first navigation and bounded review

**Sources:** BB-01, BB-02, BB-03.

The front page deliberately consists of linked showcase images. The project
keeps image review bounded with labeled sheets, item-level persisted decisions
and an early stop before exhausting its local budget.

**Transfer:** use contact sheets to preserve review context and avoid rereading
the same images. Keep a shortlist separate from user approval.

**Limit:** no prose/caption mandate should override its explicit front-page
contract. Do not reset a view budget through compaction or claim review from
decoding alone.

## 8. KnowledgeLedger: teach a route, not a pile of notes

**Sources:** KL-01, KL-02, KL-03.

Curriculum guidance sequences prerequisites and connects location, diagram,
explanation, worked example, retry, exercises and evidence. Book structures
provide chaptered learning and technical reference.

**Transfer:** distinguish activity from demonstrated understanding. The agent
can own sequencing under a teaching contract rather than repeatedly asking a
beginner to select an unfamiliar path.

**Limit:** private service-specific examples are not reusable public source
material. Only generalized pedagogy appears here.

## 9. Service-agnostic book: stable learning IDs and real production gates

**Sources:** SA-01 through SA-04.

The authoring contract has stable chapter/example/retry/question IDs and explicit
exercise/answer coverage. The production guide separates check/build/render/
finalize, previews and complete editions. Visual design notes describe proposals;
the production guide documents a later actual pipeline. The audio-direction
companion binds to a frozen textbook and native page ranges.

**Transfer:** track content structure and actual rendering separately, label
previews honestly, and keep companions bound to the correct edition.

**Limit:** chapter counts, exercise budgets, 200-page body gates and the
100-page companion contract are scoped to that book. Do not claim a fresh
dependency reinstall when only an existing local install was used.

## 10. BookMaker: presentation without corrupting canonical content

**Source:** BM-01.

The illustrated edition adapts approved reading HTML, preserves original article
bodies, uses a distinct manifest/concordance and validates native PDF output.
Source artwork and processed cutout are separate assets.

**Transfer:** an alternate presentation edition can be independent without
silently overwriting the textbook or old companion references.

**Limit:** cover overlap, supplied art and publisher-inspired aesthetics are
specific directions. They do not grant rights to reproduce a publisher's brand.

## 11. SongsWorkspace and SubwooferLullabies: creative provenance

**Sources:** SW-01, SL-01.

Native source, rendered masters, cover derivatives and website copies have
separate roles. The Blender handoff explains the actual medium, module
interfaces, environment, seeds, scene conventions, failure lessons and packaging.

**Transfer:** document creative production with the same provenance discipline
as code. Preserve editable source and selected versus experimental outputs.

**Limit:** metrics do not establish listening or aesthetic approval. Still
rendering is not animation; a runbook is not permission to rerender completed
work. Machine/GPU observations do not qualify another machine.

## 12. DeepSeaFoam: semantic design mappings

**Sources:** DS-01, DS-02.

Canonical palette roles feed generated application mappings. Native importers,
manual presets and unofficial modified-client routes have distinct boundaries.
Format/contrast tests are distinguished from installed-app inspection.

**Transfer:** document exact versus derived versus host-controlled behavior;
change canonical inputs rather than patch generated ports.

**Limit:** target count is not universal compatibility, and selected contrast
pairs are not full accessibility certification.

## 13. CareerHQ and application automation: evidence and existing alternatives

**Sources:** CH-01, LA-01.

Agent contracts and source registers emphasize attributable evidence, privacy
and scoped operational authority. The automation project's developer guide
shows a legitimate existing project organization that is not identical to the
numbered TODO preference.

**Transfer:** preserve attribution and explicitly reconcile local conventions.

**Limit:** do not convert personal records or application automation details
into public case data. A preferred template is not an automatic migration order.

## 14. Operational desks: collection, presentation and authority

**Source:** OP-01, generalized process only.

Read-only collection on a constrained access machine can produce offline inputs
for rich HTML/Markdown reports. Investigation/runbook evidence separates
observations, hypotheses, proposed action, executed action and rollback.

**Transfer:** keep snapshot/generation/reload times distinct; preserve partial
failure states and local/environment qualification boundaries.

**Limit:** no incident IDs, topology, customer data, real messages or live
production commands are imported into this public package.

## 15. Context and documentation meshes: evidence-ranked navigation

**Sources:** CTX-01, CTX-02, DM-01.

Per-base persistence and cross-base discovery complement document indexing.
Read-only source roots, separate generated output and evidence/confidence
labels prevent a graph from masquerading as complete knowledge.

**Transfer:** record discovery limits, preserve stable identities and keep
private continuity distinct from public guides.

**Limit:** index size is not semantic coverage; a social post is neither a
work ledger nor evidence that a dormant agent executed anything.

## 16. Skill Library: authored synthesis versus archived snapshot

**Sources:** LIB-01 through LIB-03.

External skills preserve exact source bytes and hashes. Public runtime payloads
have generated checksums, guarded installation and private-state separation.
This manual is a newly authored canonical synthesis, not an external snapshot.

**Transfer:** make origin classes explicit and update inventories/catalogues
with actual hashes.

**Limit:** portable payload verification is not disclosure clearance or proof
that every runtime was installed and exercised on a clean machine.
