# ClipFarm: twenty source-pinned skill copies

The [complete ClipFarm family](../skills/CLIPFARM.md) includes two core
entry points,16layout/study/review skills and two cinematic music workflows.
Every folder has a normative `SKILL.md`, operator README and substantive runbook.
Applicable examples and the generic lyric-clock helper are included.

## Current-checkout requirement

The library's older bundled ClipFarm implementation is retained unchanged.
It is not a grading-capable/current all-features runtime. This publication
copies skills/documentation/helper support, **not additional private application
code**, source recordings, transcripts, fonts, models, production ledgers or context.

Use an explicitly selected current ClipFarm checkout for the complete family:

```powershell
python .\scripts\install_skill_library.py --clipfarm-root "D:\Work\ClipFarm"
```

Replace the example with the actual permitted checkout. The installer checks
current application/support entry paths, binds the20ClipFarm definitions to it
and installs the other library entries normally. It does not modify that
checkout, its environment, data, running app, permissions or authentication.
Source access and the checkout's dependency setup are separate prerequisites;
the private upstream is not downloaded automatically.

Without `--clipfarm-root`, the existing11-entry default bulk installation stays
available. Its historical editorial runtime remains a limited baseline and
the19additional checkout-dependent entries are explicitly reported as skipped.
With a compatible root,30inventory-listed definitions are installed: the old
11plus19new ClipFarm entries. Verona remains a separate additional skill copy.

`--runtime-root` still controls the other bundled runtime copies.
`--skills-directory` selects the skill destination. Existing differing skills
fail unless the normal explicit backup-and-replace option is chosen.
Dependency restore is opt-in. With an external ClipFarm root, the library
installer never installs or changes dependencies inside that checkout; use its
own documented setup separately.

## Runtime and review boundaries

- Coding/design/complete-solve routes use real ClipFarm CLI stages.
- Native grading and A/B routes use the actual grading engine and its
  session/version/approval rules, not a second filter pipeline.
- Custom teaching/podcast/vinyl/cinematic routes require new request-local
  compositor/timeline authoring. They are not automatic scene generators.
- Full cinematic mode reviews all lyric occurrences/window progress,
  scenes/actions/joins and encoded clocks with recognition limits disclosed.
- Cinematic draft is a clearly marked full-song idea/proxy with sampled checks;
  it does not inherit full-review, user-approval or upload-ready flags.

Both cinematic routes keep the entire song unless an excerpt is explicitly
requested. Gallery UI QA and actual video lyric/cover review are distinct.
Neither installation nor a source snapshot supplies creative approval, rights,
direct listening, a calibrated display or platform upload permission.

## Verification and maintenance

Use the library validator, focused installation/reference tests and the public
payload catalogue. Test installation in isolated destinations, not over live
personal skills or a user's running media app. Do not execute a historical
producer to test an instruction copy.

Refresh normative snapshots only from an explicitly approved canonical version,
record exact hashes and reconcile current versus historical explanations.
Preserve unrelated work and private context. Do not rebuild or stage checksum
metadata from another author's uncommitted runtime bytes.
